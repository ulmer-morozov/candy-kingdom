# bonnie-cms-sample

Angular 21 SSR reference implementation for `@candy-kingdom/bonnie` and `@candy-kingdom/bonnie-cms`. Demonstrates both the public-facing site (server-side rendered) and the CMS admin UI, backed by `apps/marcy-cms-sample`.

## Running

Start the .NET backend first (it regenerates TypeScript contracts on startup):

```bash
dotnet run --project apps/marcy-cms-sample
```

Then start the Angular dev server:

```bash
npx nx serve bonnie-cms-sample
```

API calls are proxied to the .NET backend via `proxy.conf.json`.

## Build

```bash
npx nx build bonnie-cms-sample
```

## Architecture

### Public face

The `**` catch-all route resolves the current URL to a page, fetches the face view and settings, then renders via `SkeletonComponent` + `FaceBoneMap`.

```typescript
// FaceBoneMap.ts
export const FaceBoneMap = new BoneMap([
  ['text', TextBoneComponent],
  ['media', MediaBoneComponent],
  ['page-list', PageListBoneComponent],
]);
```

`FaceComponent` sets `<title>` and OpenGraph meta tags from the page data and settings.

`RouterLocalizeService` derives the active locale from the URL path prefix and implements `LocalizeServiceBase`.

### Admin UI

The `admin/**` route is lazy-loaded and guarded by `AuthGuard`. It contains:

- **Page editor** (`admin-pages`) — `SkeletonEditorComponent` + `AdminBoneMap`; saves via `AdminDataService.storePage()`
- **Settings editor** (`admin-settings`) — reads setting groups, renders type-specific form components

```typescript
// AdminBoneMap.ts
export const AdminBoneMap: BoneEditorMap = new Map([
  ['text', TextBoneEditorComponent],
  ['media', MediaBoneEditorComponent],
  ['page-list', PageListBoneEditorComponent],
]);
```

### Authentication

`AuthService` signs in/out via ASP.NET Core Identity cookie endpoints. `AuthGuard` redirects unauthenticated users. `AuthInterceptor` handles 401 responses.

### Generated types

`src/app/generated/` contains TypeScript interfaces auto-generated by `marcy-cms-sample` at startup. **Never edit these files manually.**

Key generated types: `TextBone`, `MediaBone`, `PageListBone`, `ProjectPageData`, `TextBoneStyle`, `MediaBoneStyle`, `PageListBoneStyle`, `CmsSampleSettingIds`.

## Bone editor pattern

Each bone editor follows the same pattern:

```typescript
@Component({ /* ... */ })
export class TextBoneEditorComponent extends BoneEditorBaseComponent<TextBone> {
  getPresets(): ContentPreset<TextBone>[] {
    return [
      createPreset({ title: 'Default', style: TextBoneStyle.default }),
      createPreset({ title: 'Decorated', style: TextBoneStyle.decorated }),
    ];
  }
}
```

1. Extend `BoneEditorBaseComponent<TBone>`
2. Implement `getPresets()` — one preset per style variant
3. The host directive `[boncEditable]` (driven by `SkeletonEditorComponent`) handles save/cancel
4. Emit `saved`, `removed`, `editing` outputs consumed by `SkeletonEditorComponent`
